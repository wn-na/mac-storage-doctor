# 성능 검증 기록

2026-10-18, Apple Silicon 로컬 release 빌드, macOS 26.5.2에서 기존 저장 인덱스를 사용했습니다. 배포와 사용자 데이터 삭제는 실행하지 않았습니다.

## 재현 및 비교

기존 빌드에서 프로젝트 메뉴를 열 때 긴 지연을 재현했습니다. `sample`로 12초 동안 5ms 간격으로 관측한 메인 스레드에 SwiftUI StackLayout/AttributeGraph 레이아웃 계산이 나타났습니다.

| 항목 | 기존 | 수정 후 |
|---|---:|---:|
| 프로젝트 클릭 + 접근성 트리 반환 | 18,039ms | 1,514ms |
| 최종 빌드 동일 전환 재확인 | — | 1,379ms |
| 샘플 시 physical footprint | 413.8MB | 55.8MB |
| 프로세스 시작 이후 peak footprint | 658.1MB | 61.8MB |

시간은 UI 자동화 호출과 접근성 트리 수집을 포함합니다. 순수 프레임 지연이나 통계적 벤치마크가 아닙니다. 기존 프로세스와 재시작한 새 프로세스는 실행 시간이 달라 메모리 값 역시 엄밀한 동일 조건 비교가 아닙니다. 원본 샘플에는 로컬 경로가 포함될 수 있어 저장소에 추가하지 않았습니다.

## 변경 내용

- 대량 행을 `LazyVStack`으로 필요한 시점에 생성합니다.
- 닫힌 Overview/폴더 탐색/검사 범위는 내부 뷰를 생성하지 않습니다.
- 메뉴 전환 시 이전 목록의 스크롤 위치가 남지 않도록 ScrollView identity를 변경합니다.
- 파일시스템 볼륨 조회, 검사 결과 병합과 정책 변환, 도구 의존성 조회를 백그라운드로 이동합니다.
- 볼륨 조회 중복을 막고 값이 바뀌었을 때만 게시합니다. 진행 표시는 최대 초당 4회 갱신합니다.
- 용량 관측은 계속 저장하되, 차트가 표시 중일 때만 이력을 로드하고 집계합니다.
- 검사 이력은 최근 30건의 요약만 SQLite에서 읽습니다. 전체 프로젝트/이슈 배열을 Swift 객체로 복원하지 않습니다. JSON 파싱 비용 자체가 없어지는 것은 아닙니다.

## 검증 범위

- 자동 테스트 60개, 실패 0개. 기존 정리 안전 정책·분류·SQLite·FSEvents 테스트 포함.
- 추가 테스트: 기존 검사 기록의 ID/날짜/부분 상태/프로젝트 개수, 조회 제한, 프로젝트 5,000개 및 이슈 10,000개가 있는 기록의 요약과 원본 보존.
- arm64 release 앱 빌드와 ad-hoc 서명 검증 성공.
- 실제 UI에서 프로젝트 스크롤·검색/해제, 메뉴 변경 시 스크롤 초기화, SDK 32개·Simulator 기기 26개·런타임 2개 목록 개수, 기기 목록 전환, 기록 화면의 차트와 검사 요약 표시 확인.
- 사용자 캐시·SDK·Simulator 삭제는 실행하지 않았습니다. 삭제 경로는 임시 fixture와 모의 실행기로 검사합니다.

## 남은 범위

전체 디스크 크롤 중의 장시간 상호작용, 대규모 외장/네트워크 볼륨, 다른 하드웨어에서의 프레임 지연과 실제 삭제/복원 통합 QA는 별도 검증이 필요합니다. 이번 결과로 전체 설계의 모든 수용 기준을 통과했다고 주장하지 않습니다.

## 2026-10-19 추가 경량화

- 기존 실행 프로세스에서 CPU 98.8–99.3% 및 UI 요청 타임아웃을 관측했습니다. 3초 스레드 샘플의 메인 스레드에서 SwiftUI/AttributeGraph 갱신이 반복됐습니다. 특정 사용자 동작이 루프를 유발하는 정확한 재현 경로는 확정하지 못했습니다.
- ObservableObject 전체 변경 통지에서 Observation의 속성별 관찰로 이전했습니다. 각 화면이 읽는 상태 변경에만 반응하며 시트와 설정은 Bindable로 연결합니다.
- 폴더 측정의 중복 집계 키를 문자열에서 정수 device/inode 쌍으로 변경했습니다. 단일 링크 파일은 방문 집합에 보관하지 않고 디렉터리와 다중 링크 파일만 추적합니다. 링크/하드링크 기존 테스트를 포함해 66개 테스트가 통과했습니다.
- 로컬 release 빌드에 크기 최적화(-Osize)와 디버그 심볼 제거(strip -S)를 적용한 뒤 서명합니다. 앱 번들은 du 기준 약 3.1MB에서 2,900KiB로 감소했습니다. 개발 .build 폴더 크기와는 별개입니다.
- Observation 변경 빌드를 실행한 뒤 대기 CPU 0.0%, physical footprint 54.9MB(peak 57.1MB), RSS 약 128MiB를 관측했습니다. 기존 footprint 54.2MB와 비슷해 대기 메모리 감소를 주장하지 않습니다. 대규모 분석 시 실제 절감량은 아직 측정하지 않았습니다.
- 재시작 전후 비교이므로 CPU 감소를 코드 변경만의 효과로 단정하지 않습니다. 장시간/전체 화면 회귀 검증이 필요합니다. 첫 화면 표시는 확인했지만 이후 UI 자동화 도구가 native pipe closed 오류를 반환해 추가 조작 검증을 완료하지 못했습니다.
