# Mac Storage Doctor 사용법

## 1. 분석은 필요할 때

`.npm`, `.gradle`, `.cocoapods`, CocoaPods 등 `Library/Caches` 내부는 프로젝트로 표시하지 않습니다. 기존 오탐도 현재 인덱스에서 제외하며 공용 캐시 용량 측정은 유지합니다.

메뉴바 숫자는 60초마다 가벼운 볼륨 API로 갱신됩니다. 폴더 재분석과 다릅니다.

- **캐시 분석**: 알려진 공용 캐시와 앱 데이터를 측정합니다.
- **전체 분석**: 프로젝트와 그 안의 빌드 생성물까지 찾습니다. 첫 검사는 시간이 걸릴 수 있으며 일시정지·취소할 수 있습니다.
- 기본은 **수동**입니다. 설정에서 변경 감시(15·30·60분 최소 간격) 또는 하루 한 번 캐시 분석을 켤 수 있습니다. 저장 버튼으로 적용합니다.

기존 버전에서 자동 분석이 켜져 있었다면 업데이트 시 한 번 꺼집니다. 이후 선택은 유지됩니다.

## 2. 큰 항목과 정리 방법 확인

**저장 공간 · 정리** 화면의 기본 목록은 측정된 항목 중 용량 상위 10개입니다. ‘용량 상위 10개’를 끄면 전체 결과를 볼 수 있습니다. 유형 필터와 검색을 함께 사용할 수 있습니다.

| 유형 | 처리 방식 |
|---|---|
| 빌드 생성물 | 검증된 경로는 선택/빠른 정리로 휴지통 이동 |
| 설치 의존성 | node_modules 선택 정리 가능; 재설치 필요. Pods는 진단 전용 |
| 공유 캐시 | 현재 소유 도구에서 관리; 앱 직접 실행 대상은 아님 |
| SDK · 시뮬레이터 | 별도 관리 화면에서 버전·기기를 선택해 공식 제거 |
| 사용자 데이터 | 보호; 소유 앱에서 필요한 데이터를 확인 |
| 시스템 관리 | macOS 또는 공식 관리 도구 이용 |

측정이 불완전한 항목은 정리할 수 없습니다. 순위는 접근 가능한 측정 결과 기준이며 macOS 저장 공간 분류와 같지 않습니다.

## 3. 선택 정리와 빠른 정리

1. 원하는 항목의 체크박스를 선택합니다. ‘표시된 정리 가능 항목 선택’도 사용할 수 있습니다.
2. **선택 정리**를 누르면 각 항목의 경로·소유 프로젝트·파일 변경·실행 중인 작업을 검사합니다.
3. 미리보기에서 통과한 항목과 제외 사유를 확인합니다.
4. **휴지통으로 이동**을 승인합니다. 승인한 항목만 순서대로 처리합니다.
5. **기록**에서 성공/실패와 관측 공간 변화를 확인합니다.

**빠른 정리**는 새 전체 분석 없이 기존 결과에서 재생성 가능한 빌드 생성물만 골라 같은 검증과 승인을 거칩니다. node_modules·SDK·기기 데이터는 포함하지 않습니다. 빠른 정리도 재빌드 시간이 필요할 수 있습니다.

휴지통을 비우기 전에는 용량이 바로 회수되지 않습니다. 앱은 휴지통을 자동으로 비우지 않습니다. 복원하려면 기록의 Finder 버튼으로 이동한 항목을 열고 Finder의 ‘되돌려 놓기’를 사용하세요. 직접 휴지통을 비우면 복원할 수 없습니다.

프로젝트에서 **Keep Warm**을 켜면 해당 프로젝트 생성물을 보호합니다. IDE/빌드/개발 서버가 실행 중이면 안전 검사에서 제외될 수 있습니다. 해당 작업을 종료한 뒤 다시 시도하세요.

## 4. SDK와 시뮬레이터 관리

**SDK · 시뮬레이터**를 열면 설치 목록을 한 번 자동으로 불러옵니다. SDK·기기·런타임 탭으로 목록을 전환하세요. ‘목록 새로고침’은 목록만, ‘용량 측정’은 폴더 크기까지 확인합니다. 화면을 다시 열 때마다 반복 분석하지 않습니다.

- Android SDK: NDK·build-tools·platforms·system-images·CMake의 버전과 용량을 확인하고 ‘제거…’를 누릅니다. SDK 루트를 명시한 공식 `sdkmanager`만 사용합니다. Command-line Tools가 없으면 Android Studio의 SDK Tools에서 설치해야 합니다.
- 알려진 프로젝트/AVD 참조가 있거나 Keep Warm이 설정되어 있으면 SDK 제거를 차단합니다. 동적 Gradle 설정·미발견 프로젝트·사용자 지정 AVD 경로의 의존성은 완전히 알 수 없으므로 승인 전에 직접 확인하세요.
- SDK 복원은 각 항목의 ‘재설치 방법’에 표시한 명령 또는 Android Studio SDK Manager를 사용합니다. 인터넷과 라이선스 동의가 필요할 수 있으며 앱은 라이선스를 대신 수락하지 않습니다.
- Simulator 기기: **Shutdown** 상태인 개별 기기만 제거할 수 있습니다. 기기 안의 앱·테스트 데이터가 영구 삭제됩니다. 실행 중인 기기는 Simulator에서 종료한 후 목록을 새로고침하세요.
- Simulator 런타임: 여러 기기가 공유합니다. Xcode의 Settings > Components 또는 Platforms에서 설치·제거하세요. 기기 제거와 런타임 제거는 별개입니다.

SDK와 기기 제거는 휴지통을 거치지 않습니다. 영향 확인 체크박스를 선택하고 최종 제거 버튼을 눌러야 실행됩니다.

## 5. 다시 보기와 문제 해결

설정 · 도움말에서 튜토리얼을 다시 열 수 있습니다. ‘분석 취소/이벤트 유실/재시작 후 전체 분석 필요’는 결과의 최신성이 확실하지 않다는 안내입니다. 자동으로 전체 분석을 시작하지 않습니다.

접근 오류는 설정의 제외·접근 불가 목록에서 확인하세요. 전체 디스크 접근 권한이 있어도 SIP 보호 영역은 읽지 못할 수 있습니다. 정리 실패 사유와 성공 기록은 기록 화면에 남습니다.

도구 참고: [Android sdkmanager](https://developer.android.com/tools/sdkmanager). Simulator 명령은 설치된 Xcode의 `xcrun simctl help`를 기준으로 구현했습니다.
