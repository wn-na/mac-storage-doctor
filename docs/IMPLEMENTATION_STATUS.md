# 설계 대비 구현 현황

이 문서는 원본 설계의 요구사항과 현재 코드를 구분합니다. UI에 존재하는 메뉴만으로 기능 완료를 판정하지 않습니다.

| 메뉴바 / Overview | 상주 메뉴바, 표시 전환·저용량 경고, 로그인 항목 설정, 용량 시계열 차트 | 시스템 알림 |

## HIST 대응표

- HIST-01–05: 볼륨 용량·폴더 측정·마운트 경계·차이 설명 기본 지원. 컨테이너 관계 정밀 분석은 남음.
- HIST-06–07: diskutil/tmutil 결과 조회. 스냅샷 삭제 없음.
- HIST-08–10: 시스템 경로와 MobileAsset 측정. 미등록 런타임 확정/참조 대조 미구현.
- HIST-11–12: simctl 목록·기기 상태·용량 조회와 종료된 기기의 개별 승인 삭제. 런타임 제거는 Xcode 설정 안내.
- HIST-13–14: Xcode 연결. 앱 자체 삭제 실행 미구현.
- HIST-15: DerivedData 제한 정리, Archives/DeviceSupport 진단.
- HIST-16–17: NDK 목록 및 직접 지정 버전 진단. 모든 Gradle 해석은 지원하지 않음.
- HIST-18–21: SDK/AVD 용량 진단, SDK 개별 패키지 공식 제거 및 복원 명령 기록. SDK 재설치 실행·라이선스 자동화와 AVD 자체 삭제는 미구현.
- HIST-22–29: 공유 캐시와 프로젝트 생성물 측정. 허용 프로젝트 생성물 휴지통 정리 지원. 공식 공유 캐시·프로젝트 정리 도구 실행은 미구현.
- HIST-30: 앱 bundle ID 구분. CLI 링크 체인 진단은 미구현.
- HIST-31–34: 확장·앱 지원·컨테이너 크기 진단 및 보호. 프로필별 활성 버전 분석 미구현.
- HIST-35–36: 진단 전용. 전체 Caches/VM/folders 삭제 없음.
- HIST-37: Homebrew 캐시 측정. dry-run/cleanup 미구현.
- HIST-38: Unity 설치 목록. 프로젝트 버전 매칭 미구현.
- HIST-39: App Support 보호. AI 모델 전용 탐색 미구현.
- HIST-40: 휴지통 이동 전후 관측 가용 공간 기록, 실패 사유와 미측정 구분, 이동 위치 Finder 연결. 휴지통 비우기 없음.
- HIST-41–42: 절대 경로 Process, 인자 배열, 사용자 환경 변경 없음. 셸 수정 도우미 미구현.
- HIST-43–44: 카테고리 차이 안내, 임의 폴더 읽기 전용 크기 탐색.
- HIST-45: 앱 실행 중 일일 알려진 캐시 분석. 무인 삭제 없음.

## 검증 범위

현재 58개 자동 테스트가 있으며 실제 FSEvents 수신도 검증합니다. 자동 테스트는 임시 fixture만 사용하며 실제 사용자 캐시를 삭제하지 않습니다. 분류, 숨김 프로젝트, 순수 Dart 오탐 방지, RN/Flutter 네이티브 묶기, 제외 경로, 링크·hardlink, 취소, SQLite, 마스킹, DerivedData 정책, Keep Warm, 변경·링크 바꿔치기, 보호 파일 및 내용 변경 지문을 검사합니다.

실제 디스크 전체 크롤·TCC 거부·오프라인 외장·APFS clone·실제 캐시 정리는 환경 의존 통합 QA가 남아 있습니다. 전체 v1.2 수용 기준 통과를 주장하지 않습니다.

## 증분 탐색 수용 범위

- DISC-08: FSEvents로 새로운 숨김 프로젝트 생성 감지 및 부분 재검사 지원.
- 프로젝트 제거·이동·식별 파일 변경은 범위별 병합하며, 접근 거부·취소는 기존 발견 결과를 지우지 않음.
- Quick Scan 이후 프로젝트 목록과 검사 루트 유지.
- SYS-22: 병합 인덱스 저장·재시작 로드. 재시작 공백은 전체 재검사 필요로 표시; 자동 이벤트 이력 재생은 아직 미지원.
- UserDropped/KernelDropped/RootChanged/Unmount/ID wrap 및 큰 이벤트 묶음은 전체 재검사로 복구하도록 안내.
- 감시는 전체 스캔 전에 시작하며 검사 중 이벤트를 대기열에 모아 기준 스캔 완료 후 재검사.

## 용량 이력과 정리 감사 기록

- 내부 볼륨의 실제 가용 공간을 실행 중 60초마다 SQLite에 저장하며 같은 분의 수동 새로고침은 마지막 관측으로 대체합니다.
- Overview/History에서 24시간·30일·12개월·전체 기간을 선택하고 관측 평균·최소·최대 및 첫/마지막 관측 차이를 확인합니다. 미관측 구간을 보간하지 않습니다.
- 30일이 지난 상세 관측은 주별, 12개월이 지난 관측은 월별로 트랜잭션 안에서 압축합니다. 평균은 관측 횟수로 가중하며 극값과 첫/마지막 관측을 보존합니다. 시간 가중 평균은 아닙니다.
- UTC 달력을 사용하고 주가 월 경계를 넘으면 나누어 월별 집계가 다른 달의 데이터를 섞지 않게 합니다. 일일 유지보수 및 집계 경계 때문에 보관 전환에 최대 한 집계 구간의 여유가 있습니다.
- 기존 검사·정리 JSON과 독립된 테이블을 추가하므로 기존 기록을 유지합니다. 볼륨별 분리, 재시작 로드, 중복 갱신, 경계 날짜, 반복 압축, 가중 평균, 측정 불가, 기존 정리 JSON 호환을 임시 DB로 검증했습니다.
- 정리 실행의 실패·안전 검사 중단도 이유와 함께 기록합니다. 정리 후 가용 공간을 읽지 못한 경우 변화량을 0으로 만들어 표시하지 않습니다.
- 실제 휴지통 복원 QA는 별도로 남아 있습니다. 공식 패키지 캐시 실행 어댑터는 아직 미구현입니다.

## 통합 정리 및 개발 도구 관리

- 저장 공간·캐시·Smart Cleaner를 한 화면으로 통합했습니다. 유형·방법·측정 시각·용량을 표시하며 기본은 측정된 항목 중 상위 10개입니다. 폴더 탐색은 같은 화면의 접이식 영역에 있습니다.
- 체크박스 다중 선택, 표시된 정리 가능 항목 선택, 빌드 생성물만 고르는 빠른 정리를 제공합니다. 새 전체 분석 없이 기존 결과를 재검증하고 일괄 승인 후 처리합니다. 실패한 항목도 개별 이력에 남습니다.
- 이전 분석의 프로젝트 정책을 마이그레이션하지만 실행 직전 프로젝트 식별·허용 경로·identity·지문을 다시 검증합니다.
- 기존 설치도 자동 분석·감시를 한 번 끄고 수동으로 전환합니다. 이후 사용자의 설정을 존중합니다. 일일 분석 시각을 영속화하여 재시작마다 반복 분석하지 않습니다.
- SDK는 특정 루트·패키지만 공식 도구에 전달합니다. 알려진 프로젝트·기본 AVD의 참조와 Keep Warm을 검사하며, 미확인 의존성 위험을 승인 화면에 표시합니다. 기기는 UUID와 종료 상태를 실행 전 다시 검사합니다. 삭제 성공은 목록 재조회로 확인합니다.
- 추가 테스트: allowlist·Keep Warm·이전 정책 마이그레이션, 내부/외부 링크, 상위 10개, 분석 간격, SDK 목록 파서·경로 이탈, simctl JSON·상태 변경·승인 재사용, 패키지 명령 인자와 Keep Warm 재검증, 프로세스 오류·시간 제한.
- 테스트는 임시 파일과 모의 명령 실행기를 사용합니다. 실제 SDK/Simulator 목록 형식은 읽기 전용으로 확인했으며 실제 사용자 패키지·기기·캐시를 삭제하지 않았습니다.

- 로컬 앱에서 5단계 튜토리얼의 전환·완료, 통합 5개 메뉴, 상위 10개, 유형/방법 표시, 표시된 정리 가능 항목만 선택되는 동작을 실제 UI로 확인했습니다. UI QA 중 사용자 캐시·SDK·기기의 삭제는 실행하지 않았습니다.

## 캐시 오탐 제외와 개발 도구 목록 표시

- `.npm`·`.gradle`·`.cocoapods`·`.pub-cache`·pnpm/Yarn/Maven 캐시, `Library/Caches`, Android SDK 및 CoreSimulator 내부를 프로젝트 탐색에서 제외합니다. 사용자 지정 캐시 환경변수 경로도 제외합니다.
- 전체 탐색·캐시 내부를 루트로 준 탐색·직접 분류·FSEvents 이벤트에 동일한 정책을 적용합니다. 현재 저장 인덱스의 캐시 내부 프로젝트와 그 소유 생성물은 제거하되, 공용 캐시의 용량 기록은 유지합니다. 일반 숨김 프로젝트는 계속 발견합니다.
- SDK 화면 최초 진입 시 설치 목록만 한 번 로드합니다. SDK·기기·런타임을 탭으로 구분하고 개수를 표시합니다. 용량 측정은 별도 수동 동작이며 조회 실패와 빈 목록, 미측정과 측정 불가를 구분합니다.
